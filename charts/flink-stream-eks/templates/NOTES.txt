FIRST THINGS THAT GO WRONG

  "Could not find a file system implementation for scheme 's3'"
    The plugin jar named in stateStore.builtInPlugins does not exist in your image. Check the real filename -
    the Confluent build carries a -cpN suffix:
      kubectl -n {{ .Release.Namespace }} run --rm -it --restart=Never --image={{ .Values.image.repository }}:{{ .Values.image.tag }} \
        flink-opt-ls -- ls /opt/flink/opt

  403 from S3, or "Unable to load credentials"
    The IRSA trust policy has to name this exact namespace and ServiceAccount:
      system:serviceaccount:{{ .Release.Namespace }}:{{ .Values.serviceAccount.name }}
    Confirm the webhook injected anything at all:
      kubectl -n {{ .Release.Namespace }} get pod -l app.kubernetes.io/part-of=flink-stream \
        -o jsonpath='{.items[0].spec.containers[0].env[?(@.name=="AWS_ROLE_ARN")].value}'
{{- if ne .Values.kafka.auth "none" }}

  The SQL job connects to Kafka but the DataStream job does not
    Expected, and documented in the chart README: the SQL job takes its Kafka client properties from DDL that
    this chart generates, while the DataStream job and the generator build their clients in code and ignore
    KAFKA_CLIENT_PROPS until JobConfig is taught to merge it.
{{- end }}

  Job restarts in a loop right after RUNNING
    Usually the transactional.id prefix colliding with another release on the same Kafka cluster. Give each
    release its own kafka.transactionalIdPrefix.
